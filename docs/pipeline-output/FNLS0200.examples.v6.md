# Worked examples: FNLS0200 (CALLs traced in the oracle scenarios)

FNLS0200 is a subprogram: it runs only when FNLS0100 executes `CALL ... USING FN-LOAN-REQUEST FN-CURRENCY-REC FN-MATH-CONTEXT FN-LOAN-TERMS FN-STATUS` (step STEP20 of job FNSCHGEN, clock 2022-07-05T10:11:12-07:00). These are CALLs of the faithful FNLS0200, traced from the translation that matches the GnuCOBOL oracle byte for byte: each argument as the caller passed it, then every item the CALL changed, with its value before and after. Your implementation gets the arguments as byte arrays in this order and must leave exactly these values in them (every other byte unchanged). The CALLs that show a behaviour not shown yet (other function codes or switches, other items changed, other return or status codes) are listed first from every scenario, then further CALLs spread over the scenarios.

Values are shown as the program reads them: numbers (packed COMP-3, binary COMP/COMP-5, zoned) decoded with their PICTURE's scale (1000.0000 is PIC S9(13)V9(4) holding one thousand); text in quotes without its trailing spaces ('USD' in a PIC X(10) is "USD" and seven spaces); (spaces) for a text item that is all spaces; x'00' for a text, packed or zoned item whose bytes are all x'00' (storage nobody has written: LOW-VALUES, which is not a valid packed number; a binary item of x'00' bytes is simply 0); raw bytes between « and » only for text with bytes that are not printable (\x00 is byte 0) and for a number whose bytes are not valid in its USAGE. Items still all spaces or all x'00' are left out of an argument's listing. An OCCURS table is shown as rows, only the occurrences in use (rows not listed are blank), with the columns that vary; a column with one value in every row listed is given once.
